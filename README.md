# research

公開モデル・公開フォーマットの**独立検証**と、自作の量子化・推論ランタイムの測定記録。

方針は一つだけ。**主張を自分の環境で測り直し、測れなかったものは測れなかったと書く。**
再現コマンドと生の出力を各ディレクトリに置いてある。
環境は共通で A100 80GB PCIe x8 のボックス（共有機なので同居ジョブの影響は各記事に明記）。

## 繰り返し出てくる型

四つの検証で同じ構図が出た。記録として残しておく。

**1. 「アーキテクチャの勝利」の多くは、実は別のところから来ている。**
MemT の「一般能力を維持」は backbone が凍結されているから自明に真だった。
NariQ で効いたのは trellis の作り込みではなく語彙の頻度分布を使ったヘッド分割だった。
SpikingBrain の性能は Qwen2.5-7B のものを引き継いでいる（論文はそう書いている）。

**2. 外挿と測定を見分ける。** SpikingBrain の「4M トークンで 100倍」は
1M での実測 26.5倍から曲線をフィットした推定値で、論文本文はそう明記している。
README と図の見出しはそう読めない。単一デバイスでの論文自身の数字は 128k で 1.41–2.75倍。

**3. 最適化している量を改善して、品質を落とすことがある。**
NariQ の対角ヘシアン重み付けはモジュール単位の活性重み付き誤差を 10–60% 削って、
端から端では 0.05 PPL 失った。対角はヘシアンではなく、列スケールは
trellis が必要とする incoherence を下げる。

**4. 固定サイズ状態は「無い」を表現できない。**
MemT の記憶アームは答えが存在しない問題で作話する（EM 25.35 対 full context の 84.51）。
絶対日付も失われる。グローバル attention を持たない SpikingBrain にも同じ型の問いがある
（[spikingbrain-7b](spikingbrain-7b/) の needle テスト）。

## 測り方について

各記事に再現コマンドとハーネスのソースを置いてある。共通して守っていること:

- **判定器を使わない指標を優先する**。実行ベースの pass@1、文字の対数確率、
  perplexity、exact match。LLM 判定は再現しないし、条件を揃えにくい。
- **比較する二つのアームで指標を完全に同一にする**。違うのは測りたい一点だけ。
- **ディスクオフロードを検出して中断する**。`max_memory` が足りないと一部パラメータが
  `meta` デバイスに載り、静かに別物を測ることになる。全ハーネスが起動時に弾く。
- **絶対値を他者の論文と比べない**。thinking の有無、判定器、プロンプトが違えば
  絶対値は比較できない。意味があるのは同一条件下の差分。

```python
meta = [n for n, p in model.named_parameters() if p.device.type == "meta"]
if meta:
    raise SystemExit(f"ABORT: {len(meta)} params on meta; raise --mem")
```
